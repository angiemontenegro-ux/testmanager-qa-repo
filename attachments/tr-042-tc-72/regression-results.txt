OBS-1 (observacion, NO defecto) — Order Cost = $0.00 en fila a medio llenar
-------------------------------------------------------------------------------
El bloque restaurado multiplica sin guardia:
    orderCost.value = itemCost.value * orderQuantity.value;
Con `order-quantity` en `value: null` (fila nueva sin cantidad), 25 * null = 0,
por lo que Order Cost muestra $0.00 en vez de quedar en blanco. Al escribir la
cantidad, handleChangeInput recalcula bien.

Por que NO se clasifica como defecto:
  1. Es comportamiento PREEXISTENTE restaurado, identico al de antes de SH-942.
     El revert no lo introduce.
  2. El mismo idiom sin guardia ya vive en ShopInventoryWizardHelper.js:54
     (`itemRow[7].value = shopItem.Auctifera__Item_Cost__c * systemInventory`),
     o sea es patron del repo, no desliz de este PR.
  3. No contradice ningun AC. El AC5 dice "Order Cost equals Item Cost x Order
     Quantity"; con cantidad vacia, 0 es consistente con esa formula.
  4. Impacto cosmetico: un campo currency de solo lectura (order-cost tiene
     `disabled: true`) mostrando $0.00 transitoriamente.

Asimetria colateral observada: el controller SI protege el recomputo
(`if (itemRow[2].value && itemRow[3].value)`) pero el helper NO. Queda a criterio
del equipo si vale unificar.

OBS-2 — truthiness con costo 0 en la rama del Variant
El controller usa `else if (itemRow[0].cost)`. Si el costo base es 0 (falsy), al
elegir un Variant sin Cost_per_item__c no cae al fallback. Borde muy estrecho;
el camino de limpiar el Variant (`itemRow[2].value = itemRow[0].cost`) si maneja 0.
